# Output Contract（report.md 收尾契约）

`report.md` 是任务唯一的过程文档义务：任务完成（或明确终止）时，由执行者**直接编辑任务目录下的骨架**填充为完整报告。验收人按本契约核对内容真实性（报告里的命令应可一键复跑）。

## 通用规则

- 文件名保持 `report.md`（小写），标题、正文、项目符号说明使用中文；只有代码、文件名、命令名、协议字段名、接口字段名保留原文。
- 内容必须来自真实做过的事：未跑通就如实写未跑通与卡点，禁止空洞占位、禁止虚构过程。
- 会话标识、凭据与存储快照必须脱敏：只保留键名、长度、哈希、前后缀、过期时间等最小验证信息。
- 收尾时删除骨架注释与提示行；不得保留骨架标记或仅标题空节。
- 未核实文件真实存在前，不得写“已落盘”；未拿到最新验证结果前，不得写“已成功”。

1. **任务概览** — 用户目标 + 实际结果/偏差 + 最近验证状态。
2. **分析与路线决策** — 选中路线 + 理由 + 至少一个替代方案或无替代的依据。
3. **实现路径** — 1～5 个有序步骤，每步回指关键证据。
4. **任务难点** — 未解决边界及影响，或当前无未解决难点的验证依据。
5. **任务坑点** — 症状/误导 → 纠正 → 防复发，或未遇到影响结果坑点的检查范围。
6. **外部约束与检查记录** — 约束及证据，或已检查的范围。
7. **关键曲折与试错记录** — 一个证伪/pivot/转折，或一次收敛的具体依据。
8. **核心逻辑与实现方案** — 机制或逻辑边界、输入输出、fixture/验证层级。
9. **资产沉淀与方法论升级** — 一条可跨任务复用的规则/工具/检查表/eval 改进及适用边界。
10. **成果及使用示例** — 真实产物路径 + 可执行命令 + 最小输入/输出或实测结果。
11. **其它** — 至少写限制、清理、未纳入范围、后续建议之一；无则写“无”。

| 1 | 任务概览 | 用户要什么，实际交付到哪一步？ | 用户目标 + 实际结果/偏差 + 最近验证状态。 | 不允许 N/A；阻塞或终止也要写清已完成、未完成和当前边界。 |
| 2 | 分析与路线决策 | 为什么选这条路线，放弃了什么？ | 选中路线 + 选择理由 + 至少一个替代方案，或基于证据说明为何不存在可行替代。 | 不允许 N/A；硬阻塞前写已尝试证据与阻塞点。 |
| 3 | 实现路径 | 如何从输入走到当前产物？ | 1～5 个有序步骤；每步回指关键文件、函数、端点、断点、命令或产物。 | 不允许 N/A；未完成时列到最后一个真实可执行步骤。 |
| 4 | 任务难点 | 当前仍难或未知的边界是什么？ | 未解决边界及其对验收的影响，或给出无未解决难点的验证依据。 | `当前无未解决难点：<依据>`；裸“无”失败。 |
| 5 | 任务坑点 | 哪个具体错误或误导最容易复现？ | “症状/误导 → 纠正 → 防复发”闭环，或未遇到影响结果坑点的检查范围。 | `未遇到影响结果的坑点：<检查范围/依据>`；裸“无”失败。 |
| 6 | 外部约束与检查记录 | 任务受哪些环境或外部条件约束？ | 环境/依赖约束及证据；没有命中时写已检查范围。 | `未命中：<已检查信号/范围>`；不得为普通任务编造约束状态。 |

| 8 | 核心逻辑与实现方案 | 实际机制/逻辑边界及输入输出是什么？ | 机制或逻辑边界、输入输出、fixture/验证层级。 | 不允许 N/A；机制不明时写已确认的边界。 |
| 9 | 资产沉淀与方法论升级 | 什么可跨任务复用？ | 可跨任务复用的规则、工具、检查表或 eval 改进，并说明适用边界。 | `本任务无跨任务新增：<依据>`；裸“无”失败。 |
| 10 | 成果及使用示例 | 用户拿到什么，怎么使用？ | 真实产物路径 + 可执行命令 + 最小输入/输出或实测结果。 | 不允许 N/A；阻塞任务也列真实部分产物和实际阻塞输出。 |
| 11 | 其它 | 还有什么限制、清理、未纳入范围或后续建议？ | 至少写限制、清理、未纳入范围、后续建议之一；没有则写“无”。 | 允许唯一裸 `无`；本节不得承载隐藏状态字段。 |

### 解析与内容边界

- 顶层只认代码围栏外、真实 ATX H2（`## `）；允许 `###` 子节，不允许额外顶层 H2。
- 接受 CRLF；正文不能通过 trim 伪造非空。
- 第 2 节与第 7 节、第 4 节与第 5 节按内容分工，禁止整段复制。
- N/A 必须是“状态/对象 + 原因”，不能只写关键词；不设置统一字数下限。

## 领域要点归置

任务涉及特定领域时，把领域要点放进最相关的固定小节（不另开文件）；领域知识由使用者自备，本契约不预设任何领域清单。

任务产物放在任务目录内任意位置，并在「成果及使用示例」列出真实清单、可执行命令和最小结果；其中必须明确可复跑命令（`复现命令`）和实测输出，不再要求固定的 `run/xxx-notes.md` 命名。

## 完成判据（文字红线）

- “已完成 / 已交付”只能在最终示例代码真实跑通（可独立运行、服务端实测成功）之后说。
- 交互确认类任务的验收 = 端到端服务端返回成功，不是“格式被接受 / 字段齐全”。
- 局部样本、单点成功、偶发成功都不算验收。
- 交付物 = 可运行示例 + 固定 11 节 `report.md`，不是口头宣称。
- 旧报告保持只读，不自动迁移，不因本轮检查被覆盖。
