# Deliverable Ladder

先确定要交什么，再决定要不要继续深挖。

## 验收严格度分级（交付梯度）

| 梯度 | 默认目标 | 最小交付 | 不要过度建设 | 何时适用 |
|---|---|---|---|---|
| 服务端验收通过 | 目标请求 / 操作被服务端稳定接受 | `report.md` + 验收脚本 + 样本/输入映射 | 不要默认强做更重的实现路线 | 授权属性为 ①②③ 且目标域在授权范围内时的默认终态 |
| 浏览器内一致性 | 同一验收在浏览器内稳定完成 | 一致性说明 + 验证样本 + 验证脚本 | 不要把单次成功误当稳定完成 | 服务端验收条件不满足、或用户明确以浏览器为准 |
| 本地自检通过 | 本地实现可控、可复算 | 最小调用链、fixtures、verify 脚本 | 不要为了"完整"无边界扩实现 | 授权属性为 ④（仅本地分析）时的完成判据（配合浏览器内一致性对比） |

更高的严格度不是"更好的报告"，而是更强的验收证据。降级交付梯度不等于降低真实性：report.md 必须如实标注当前达到的梯度。

## 报告详实度轴（reportDepth，与交付梯度正交）

`deliverableTier` 决定「交什么成品」，报告详实度决定「report.md 写多详细」，两者正交，按任务需要自定（用户要详细报告即 deep）：

| 详实度 | 适用 | 对 report.md 的要求 |
|---|---|---|
| `brief` | 纯验收通过、用户只要结果 | 固定 11 节仍必填，但实现路径/分析与路线决策可从简（一两句） |
| `standard`（默认） | 常规任务 | 固定 11 节写实 |
| `deep` | 研究型 / 用户明确要详细报告 / 提示词命中「详细报告 / 怎么实现 / 原理 / 难点 / 过程」 | 固定 11 节写实且展开：输入清单、关键推导、数据流图、失败尝试全部入文（对应 output-contract「领域要点归置」） |

无论详实度取值，「成果及使用示例」节必须含可复跑命令与实测输出。

## 用户目标强约束

如果用户明确要求：

- `纯 Python`
- `纯 Node / NodeJS`
- `不依赖 Playwright / Puppeteer / 浏览器框架`
- `本地完成目标请求的完整复算`

那么：

- 浏览器侧 PoC 不能直接当最终收尾
- 最多只能作为 `浏览器内一致性` 的中间证据
- 若本轮只能交付浏览器方案，必须显式写：`原目标尚未完成 + 当前梯度 + 下一步迁移边界`

## 选择规则

- 每轮保留 1 个主梯度 + 最多 1 个备用梯度
- 默认先满足当前最小交付，再决定是否升级
- 如果用户只要请求成功，不要把任务偷偷升级成"完整实现论文式交付"
- 如果后续证据表明当前梯度选高了，允许主动降级：例如从 `服务端验收` 降回 `浏览器内一致性` 或 `本地自检`

## 何时应该主动降级交付梯度

满足以下任一情况时，优先考虑降级，而不是继续硬顶高梯度：

- 较低梯度已能稳定逼近验收，但更高梯度的实现路线连续两轮无新增验收证据
- 当前最关键的未知项仍在会话态 / 生命周期 / 使用点，而不是实现本身
- 用户真正要的是验收通过或一致性结论，而不是长期运行件
- 当前深挖路线的成本已经明显高于它对最终交付的增益

## 降级不影响核心交付

降级意味着换一条更便宜、更贴近验收的路线，不意味着放弃用户需求。
降级时必须声明：
- 原梯度是什么
- 为什么当前梯度太高
- 降级后的新梯度是什么
- 哪些高成本路线被暂停（不是永久放弃，而是等更便宜的路线打通后再评估）

### 降级缓冲

降级后在新梯度至少执行 **3 轮**才能再次降级，防止降级螺旋（刚降级 → 1 轮不适应 → 再降级 → 最终降到最低梯度以下）。降级后的前 3 轮为"梯度适应期"：不触发停损 pivot 但每轮仍需有效推进记录，连续 3 轮零推进仍触发复盘。第 4 轮起正常计轮。提前降级需满足 3 条件（核心路径被证明不可行 + 具体证据 + 非主观判断），连续两次提前降级触发强制复盘。完整规则见 `stop-loss-parameters.md`。

停损参数以 `docs/reference/stop-loss-parameters.md` 为单一致源。

## 本地经验在梯度决策中的作用

在决定升级或降级前，先检索本地经验（task-local 历史 + knowledge cards）：
- 同类任务历史上哪个交付梯度最终完成了验收？
- 是否有 known pitfalls 警告不要过早升级？
- 如果本地经验提示"同类场景中更高梯度的成功率极低"，优先保持当前低梯度

本地经验不能替代当前任务的验证，但可以作为梯度决策的参考权重。
