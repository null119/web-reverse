# 法律与案件安全规范（Legal & Case Safety Policy）

## 授权与法律维度（红线 3 细则）

### 任务属性四选一（开工硬性前提）

`task-init` 在任务目录创建 `AUTHORIZATION.md`，开工先把任务归类并勾选：

1. ① 自有资产（本方拥有或运营的站点、小程序、接口）；
2. ② 有书面授权的安全评估（记录授权方、范围、期限、证据编号）；
3. ③ CTF / 公开靶场 / 自建环境；
4. ④ 公开合规研究（只做本地分析，不向真实业务端点提交任何请求）。

无法归类时先向用户索要授权依据；索要不到即终止任务。

勾选多项任务属性视为登记无效（只允许四选一）：验收工具检测到多勾时按未登记处理（exit 4、零请求），须重新登记后方可服务端验收。

### 永拒类别（无论是否声称"有授权"）

代抢/代拍/秒杀/刷量/刷单；验证码代打或对外提供验证码破解服务；对无授权第三方的批量数据爬取（尤其含个人信息）；DRM 解密产物的对外分发、传播或批量提取存储（授权范围内的解密链分析与本地明文帧验证不在此列：仅限属性 ①②，产物仅留任务目录、仅向授权方交付）；账号盗用/撞库/凭证提取辅助；以欺诈或牟利为目的的支付通道绕过与风控欺骗；改包后的客户端对外分发。

### 服务端验收分级

- 属性 ①②③ 且目标域在授权范围内：允许服务端验收（`run/verify-once.mjs` / `scripts/verify/verify-offline.py`，多轮 + 间隔）。
- 属性 ④、未勾选、授权文件缺失或域不匹配：禁止向真实目标提交请求；完成判据降级为算法自检（`verify-algo.py`）+ 浏览器内一致性对比，report.md 如实标注交付梯度。
- `verify-offline.py` 内置授权闸门（未登记/未授权域 exit 4 且零请求）。闸门约束验收编排层，不防御实现模块自身的网络副作用——实现者须自行遵守。Node 侧同口径：闸门仅约束从仓库模板复制的验收编排层及其副本；任务期自写脚本、任意其它文件名（如 check-server.mjs）、直接以 curl / 浏览器发请求、模板复制后删改闸门段，均不在拦截范围——实现者须自行遵守红线 3。
- Node 侧使用仓库模板 `scripts/verify/verify-once.template.mjs`（复制到任务目录 run/ 下改名 verify-once.mjs），内置同款闸门与 audit.log 留痕。

### audit.log 留痕

服务端验收工具每次放行请求后自动向任务目录 `audit.log` 追加一行（时间 / host / 轮次 / 授权属性 / 域来源）。这是**验收工具的自动副作用**，不属于 SKILL「过程零强制记录」针对的模型过程文档义务。`AUTHORIZATION.md` 的「登记时间」字段由执行者勾选时填写，作为登记动作留痕。二者共同对应白帽四件套中的「书面授权 + 限定范围 + 留存日志」。

### 分发约束

**分发决策记录**：2026-11-04，仓库所有者（null119）完成分发评估后明确解禁，本仓库以**公开分发**形态发布（github.com/null119/web-reverse，Apache-2.0）。原两项分发决策点（获取者核验上线、外部法务审阅）由所有者自行承担评估结论；公开形态下匿名克隆不做逐获取者核验登记，改由滥用响应三级处置与 [abuse-report] issue 渠道承担事后追责，口径见 `distribution-and-abuse-response-policy.md`。永拒类别清单（见上文红线 3）不因解禁而放宽。

## 数据卫生维度

### 目标

- 把公开层与 task-local 执行层分开
- 不把站点细节、凭证、敏感数据写入公共文档

### 约束

- `artifacts/tasks/<task-id>/` 只服务当前任务
- Cookie、storage、header、响应样本默认只保留**最小验证快照**；能摘要就不要整包保存
- 如必须保留会话样本，优先写 redact 后版本，例如只保留键名、长度、哈希、前后缀或过期时间
- `live-browser-response-body.txt`、原始 cookie 串、整包响应正文不应成为默认交付；只有在无法替代且对当前任务验证必要时才保留
