# 分发与滥用响应政策（Distribution & Abuse Response Policy）

> 本政策是 `web-reverse` 仓库分发与滥用响应侧的执行文件。分发决策记录见
> `docs/reference/legal-and-case-safety-policy.md`「分发约束」。

## 供给对象口径

本仓库为单一版本治理框架（不含任何领域执行知识）。2026-11-04 所有者解禁分发后，本仓库以公开仓库
形态（Apache-2.0）对外供给：匿名获取（克隆/复刻）不做逐获取者核验登记；对本仓库或其派生产物的
**定向供给**（私有版本、定制派生、代办转交等非公开渠道）仍须先按本政策完成获取者核验四步登记。

## 获取者核验（四步登记）

向任何对象供给本仓库（或其派生产物）前，按顺序完成四步登记并留档：

1. **身份**：确认获取者真实身份（个人 / 组织、联系方式）。
2. **用途声明**：获取者书面声明用途（自有资产评估 / 授权评估从业 / 研究等）。
3. **授权证明或雇主证明**：安全评估从业身份须提供雇主证明或既往授权案例佐证。
4. **分发记录**：登记版本 / 对象 / 时间，形成可追溯的分发台账。

## 滥用响应（三级）

收到滥用线索或反馈后按三级响应处置：

1. **核实**：对照分发记录与反馈证据核实是否属实。
2. **停止向该方供给**：核实属实即停止向该获取方继续供给（含后续版本）。
3. **必要时停发回收并留证**：影响面大时暂停分发、召回已分发副本，并保留证据链备查。

（三级响应对应真实社区案件中"事后处置"能力的直接要求：分发方必须有能力在事后切断供给并留证。）

## 滥用反馈入口（intake）

滥用反馈入口：仓库 issue（标题前缀 [abuse-report]，模板字段：涉事版本/用途描述/证据链接）——公开分发后此渠道即时生效（github.com/null119/web-reverse/issues）；收到反馈按本政策三级响应处置。

## 季度复查

每季度对照红线清单（`docs/reference/legal-and-case-safety-policy.md` 永拒类别）与终态目录结构复查新增文件：
新增内容若引入对抗性执行知识，必须先过红线 3 与分发约束评估（发布前人工检查第②条）。
