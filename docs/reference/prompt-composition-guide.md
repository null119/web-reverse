# Prompt Composition Guide

本文件承接 `PROMPTS.md` 中不再保留的长变体与组合建议。  
原则是：`PROMPTS.md` 只保留最常用模板，本文件承接组合技巧与扩展例句（治理框架口径：授权属性 / 验收标准 / 收尾契约的组合策略）。

## 1. 组合顺序

推荐顺序：

1. 新任务 / 续跑任务模板
2. 验收导向
3. 交付梯度说明
4. 结论精度
5. 收尾 / Closeout

## 2. 适合下沉到扩展层的长说明

以下内容通常不必每次都塞进顶层提示：

- 好/坏示例对照
- 长格式暂停示例
- deliverableTier 降级解释模板
- 浏览器侧取证与外部检索的取舍说明

只有当前任务真的卡在这些决策点上，再按需补回。

## 3. 可选扩展句

### deliverableTier 降级

```text
如果执行中发现当前 deliverableTier 选高了，请主动降级到更贴近验收的一层，并说明：
- 为什么原梯度过高
- 降级后新的主目标是什么
- 哪个高成本路线被暂停
```

### 验证深度解释

```text
请顺带说明：
- 为什么当前验证深度最贴近验收边界
- 哪条备用路线如果默认两轮不再提供新证据，就会被移出预算；若该路线已开启深挖 permit，则改按 permit 预算判断
```

### 外部资料检索（如可用）

```text
如果你准备进行外部资料检索，请先说明：
- 为什么当前不是更适合继续本地验证
- 这轮检索准备纠正哪一个判断
```

### 精确暂停示例

```text
- blocked-on-user
- blockingAction: 集成环境已到登录页，但目标操作依赖登录后的会话状态
- requiredUserAction: 现在请登录，并停留在目标页面不要刷新
- resumeCondition: 看到登录后的目标请求完成后立即继续
```

## 4. 何时不需要扩展句

以下情况不必补长模板：

- 只是常规新任务启动
- 只是续跑 task-local
- 当前主线已很清晰
- 暂无 deliverableTier 降级、外部检索取舍、或路线 pivot 争议

## 5. 顶层瘦身原则

- 顶层保留高频模板
- 低频长模板放这里
- 规则真源仍是 `SKILL.md`
- 收尾契约真源是 `docs/reference/output-contract.md`
